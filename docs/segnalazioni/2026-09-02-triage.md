## Why August reads as untouched

**There is exactly one user account in the org.** `GET /api/v1/users` returns a
single row. All 158 segnalazioni carry that one `user_id`. Nobody is looking at
the wrong login, and no second account holds a separate backlog.

**Nothing is unpushed.** `git rev-parse HEAD origin/main` match; `git log
origin/main..HEAD` is empty.

Two independent causes, neither of them lost work:

1. **`status` is only ever changed by an admin PATCH** (`PATCH /feedback/{id}`).
   Shipping a fix does not move a row to `risolto`. Commit `63acc80`
   (2026-08-14, deploy `dep-d9viqks9v7es739hcakg`, live) implemented the entire
   Aug 3–5 batch and every one of those 20 rows is still `nuovo`.

   the repo; rows that never became issues were never on the board.
